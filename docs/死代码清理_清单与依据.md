# 死代码清理：清单与依据

> 本次清理是前两次改动（`5f04a8d` 海康→大恒 SDK 迁移、`ed66c77` 卡死排查）之后的收尾。
> 目标有两个：确认海康 SDK 是否还有残留，以及清掉无人引用的代码。
>
> **删除是破坏性操作，所以每一项都先做了引用核对，下面把依据一并记下。**

## 一、海康 SDK 残留：只剩注释，无一行代码

全仓库扫描 `MvImport` / `MvCamera` / `MV_CC` / `MV_FRAME` / `MV_GIGE` /
`MV_ACCESS` / `CameraParams_` / `PixelType_` / `MvErrorDefine` / `hikvision` / `MVS` / `海康`：

| 位置 | 性质 |
|---|---|
| `Camera_Tool/CameraOperation.py:6-10` | 模块 docstring，说明"为什么从海康换成大恒" |
| `main_yolo.py:295` | 注释，说明回调里不再手工做像素转换 |
| `main_yolo.py:825-826` | 注释，说明 `DeviceManager` 构造已等价于旧的 `MV_CC_Initialize` |
| `config.yaml:451` | 注释，说明 `buffer_count` 的来历（旧实现硬编码为 1） |

**这 8 处全部是注释/文档字符串，没有任何可执行代码。** 它们解释的是"为什么改成现在这样"，
删掉会让后来人重新踩坑，因此**有意保留**。

实体文件层面，海康的东西在 `5f04a8d` 就已删干净：

- `lib/MvImport/`（6 个 ctypes 封装：`CameraParams_const.py`、`CameraParams_header.py`、

  `ParametrizeCamera_AreaScanIOSettings.py`）

## 三、排除的假阳性（这些**没有**删）

静态扫描会误报，以下几项经复核确认在用：

| 被误报的 | 实际情况 |

| `lib/gxipy/` 下 9 个模块（`gxiapi.py`、`gxidef.py`、`ImageProcess.py`、`Decompressor.py`、`MediaProc.py` 等） | 扫描脚本按仓库相对路径算模块名为 `lib.gxipy.*`，而代码是以顶层包 `gxipy` 导入的（`lib/` 在 `sys.path` 上）。`lib/gxipy/__init__.py:5-12` 里 `from gxipy.gxiapi import *` 等确实全部在用 |

| `AnomalyDetection_Tool/YoloDinomaly/` 下 4 个模块 | 包内相对导入（`from .models`、`from .data`），扫描跳过了 `level > 0` 的相对导入 |
